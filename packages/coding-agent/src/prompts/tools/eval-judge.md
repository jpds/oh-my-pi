```
await judge(state, questions) → `{id: answer}`
    Typed judgment over one `state` (str | JSON object | JSON array). Every question sees the same state and is answered independently: batch independent questions into one call. Cheap and fast (TypeSafe when credentialed, else the tiny/smol chat model); prefer over a plain chat call for classification, yes/no, ranking. Two or more states → `{{#if py}}judge_batch{{else}}judgeBatch{{/if}}`, never a loop of `judge()`.
    `questions`: dict keyed by id (`{id: q}`); a list of `{id, ...q}` entries also accepted; q is one of
      `{type: "choice", instructions, criteria: {label: rubric | None, …}}` → `{choice, probabilities: {label: p}, confidence}` (≥2 labels)
      `{type: "bool", instructions, criteria?: {true?: str, false?: str}}` → `{bool: P(yes)}`
      `{type: "score", instructions, criteria: [lowest, …, highest]}` → `{score, probabilities: {"0": p, …}, confidence}` (≥2 levels; score is the probability-weighted level index)
{{#if py}}judge_batch(states, questions, concurrency?=32, retries?=1, min_ok?=1, intent?=None) → JudgmentBatch{{else}}judgeBatch(states, questions, { intent?, concurrency?, retries?, minOk? }) → JudgmentBatch{{/if}}
    Returns at once (host-owned when judging goes through the tool bridge; with a native judge it runs kernel-local. In Python the batch is awaitable and resolves to itself, so `await judge_batch(…)` also works).
    Same `questions` over every state (`{key: state}` or a list keyed by index), run and owned by the host on the bridge path (it outlives the cell){{#if py}}; under a native judge the run is kernel-scoped: not a host job, so `wait`/completion auto-delivery/`agent://` addressing don't apply and `cost` reads 0.0{{/if}}. `intent` is an optional nonempty progress/job label (default `"Judging"`). Pull settled items in bounded slices across cells: `{{#if py}}await b.drain(timeout?){{else}}await b.drain({ timeout }){{/if}}` → `[(key, item)]` settled since the last drain; always a list, `[]` when nothing settled (item = `{key, answers, error, model}`, `item.answers` on success else `item.error`, never raised); a drain returns once ≥1 item settles (+0.1 s coalesce), not on completion; to collect everything, loop `drain()` until `[]`; `{{#if py}}async for k, item in b.drain_iter(timeout){{else}}for await (const [k, item] of b.drainIter({ timeout })){{/if}}` until timeout or completion; `b.status()` → `{intent, done, total, failed, cost, running, model}`; `b.results()` → `{key: item}` (same item shape, all settled items); `b.failed()` → `{key: error}`; `b.cancel()`; `b.close()` releases it. `drain()` raises only when the run died wholesale (no judge, or fewer than `min_ok` answered). `b.id` is an async job id on the bridge path: completion auto-delivers a summary, `wait` blocks when you have nothing else to do; `{{#if py}}judge_batch{{else}}judgeBatch{{/if}}.attach(id)` re-creates the ref after a reset ({{#if py}}kernel-local runs: within the same kernel only{{else}}host-owned runs{{/if}}).
```
